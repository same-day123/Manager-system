## 3. 边界（**不要做**）

- **不要**自己编技术内容、数字、结论。所有内容来自 D1 定稿文档与代码事实；**文档里没有的先问，不猜**。
- **不要**把任务卡、提示词、项目文档的表格原文粘进 PPT。查重红线只对 5 份文档生效，但同源文本反复出现同样会拉高整包重复率，答辩时也一眼看得出是机器拼的——**必须重写表述**。
- **不要**用整屏代码截图做代码走读。投影分辨率下必然不可读。
- **不要**在代码冻结（**T-3 天**）之后重截系统界面。会造成截图与代码不一致。
- **不要**使用系统 UI 里不存在的颜色或自创配色方案。**PPT、海报、系统界面必须同一套色。**
- **不要**引入需要联网下载的字体、图标包、模板素材（本机离线）。
- **不要**把 `00` 号文件「明确不做」清单里的东西画进方案图（如预约模块、小程序端），否则等于自己制造需求与实现偏差。
- **不要**倒过来改文档来迁就 PPT。依赖方向是 `D1 → D2`，单行道。
- **不要**因为做海报而推迟 T0~T5。海报是加分项，任务书没要求。

## 5. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **3 分钟不是「删一点就行」** | 700 字 ÷ 8 页 ≈ 88 字/页。**必须按「一页一个结论」重写**，不能从文档里截段落。这是本卡最容易做错的地方。 |
| **15 页含封面与附录** | 别把封面、致谢、附录当"不算页数"。14 页的分配已经算进去了。 |
| **提问备份页是加分设计** | 5 分钟提问环节，老师问到权限/数据模型/不足——**当场跳备份页**，比翻 5 份 PDF 快得多，观感也好。 |
| **第 5 页是"反向得分"页** | 「为什么不做预约模块」「为什么不用状态模式」是**主动做出的技术判断**（见 `00` 第 3.2 节）。讲取舍比堆功能得分。 |
| **第 12 页同理** | 主动讲 D-01/D-06/D-08 的偏差与权衡，对应评分点「承认不足并说明改进思路」（问答应对 7 分）。 |
| **截图必须能复现** | 用演示账号（`labadmin` 等，密码 `123456`）在真实环境跑出来。老师让现场演示时，画面必须和截图一致。 |
| **测试/流水线截图要对得上数字** | 截图里的 `Tests run: N` 必须与 T1、T2 台账一致。对不上就是自曝其短。 |
| **代码走读不要整屏截图** | 投影下 12px 代码是糊的。做法：选 8 行关键代码（建议 `LabRepairServiceImpl.validateStatusChange`），放大到 ≥ 24px，问题行加红色高亮框 + 一行注释。 |
| **本机离线** | 不允许依赖 Google Fonts / 在线图标库 / 在线模板。中文字体用系统自带的微软雅黑或思源黑体。 |
| **PPT 也要做 PDF 导出** | 答辩机不一定装了你用的软件。PDF 是保真的兜底，且任务书允许「PPT/PDF」。 |
| **与 T6 的联动** | 系统界面的最终观感由 T6 决定。T6 未完成前，界面截图会作废——**先做不依赖截图的 1~8 页，截图留到 T6 收口后再取**。 |
| **色值不要手抄错** | 一律以 `laboratory.scss` 的变量为准。2026-09-17 复核时该文件已存在（见 T6 卡第 9 节），**不要再新建它**。 |
