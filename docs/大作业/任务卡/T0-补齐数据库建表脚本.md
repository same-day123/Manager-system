### 索引约定


## 5. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **`model` 是敏感列名？** | MySQL 里 `model` 不是保留字，mapper XML 里也是裸写 `a.model`，**不要**加反引号，保持一致。 |
| **两张记录表的 DDL 会被重复定义** | `laboratory_schema.sql` 建一次、`laboratory_upgrade.sql` 再建一次。因为都用 `if not exists`，无害。**但两边字段必须完全一致**，照抄 `laboratory_upgrade.sql` 的内容，不要自己改长度。 |
| **`lab_repair` 的 4 个"升级字段"** | `attachment_urls` / `rating` / `evaluation_content` / `evaluation_time` 只在 `laboratory_upgrade.sql` 里以 `alter table` 形式出现。新脚本建表时**必须一次性带上**，否则 `laboratory_upgrade.sql` 的存储过程会在已有列时跳过，不会报错但也没建——一跑 Java 就 `Unknown column`。 |
| **`laboratory_upgrade.sql` 用了 `delimiter //`** | 用 `mysql < file` 方式导入没问题；如果用 Navicat 之类的 GUI 逐个执行，注意它是否支持 delimiter 切换。**验证时统一用命令行导入**。 |
| **本机 mvn 启动脚本是坏的** | 与本事无关，但如果顺手要跑测试，用 `.workbuddy/tools/mvnx.ps1`，别直接敲 `mvn`。 |
| **Git Bash 可能挂** | 本机 Git Bash 的 PATH 曾多次损坏（`ls`/`dirname` 找不到）。命令跑不通就换 PowerShell，并记得 PowerShell 的 stdout 有时不返回，需要 `Out-File -Encoding utf8` 落盘再读。 |
