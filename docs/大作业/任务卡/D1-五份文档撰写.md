## 3. 边界（**不要做**）

- **不改代码**：`RuoYi-Vue-fast/src`、`RuoYi-Vue3/src` 一律不碰。缺素材去找对应角色要。
- **不编数据**：测试数字来自 T1/T2，流水线来自 T3/T4。拿不到就标 `[待填]`，**不猜、不估算**。
- **不写没有实现支撑的功能**：`AGENTS.md` 第 7.2 节「需求→实现对照」是唯一事实来源；
  `00` 号文件「明确不做」清单里的东西（预约模块、小程序端）**不许写进文档**。
- **不把任务卡 / 提示词 / 表格原文粘进 PDF**——查重率 >30% 该项 **0 分**。
- **不改 `AGENTS.md` 的 5.1 / 6 / 7 节**（产品经理的台账）；你只在第 5 节台账**追加**自己一行。
- **不为凑页数灌水**：页数是区间不是目标，内容不够先补证据（截图、表格、图），不要注水。

## 5. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **70 分里最容易丢的是"硬指标没逐项对上"** | 五份文档各自有明确指标（见 1.1）。**先做一张自查表**，每写完一份就勾，别等最后统一检查。 |
| **查重红线只对 5 份文档生效，但同源文本照样拉高整包重复率** | 任务卡、提示词里的表述**必须重写**。AI 生成的初稿往往与提示词高度同源——**人工改写是必做项，不是可选**。 |
| **需求文档已经"超额"** | `01-需求基线.md` 有 14 个用户故事（要 ≥10）、6 组 GWT（要 ≥5）。**成文即可，不要再造新故事**——造了反而与实现对不上。 |
| **架构文档的 SOLID 要"指到类"** | 泛泛说"我们遵循 SOLID"不得分。做法：DIP 指 `Controller → ILabXxxService → Impl`；SRP 指 `LabRoleUtils` 单一职责；开闭/里氏指具体扩展点。 |
| **设计模式章节等 T5** | `T5` 落地「简单工厂」后，类图才有得画。**T5 未完成前，这一节先留骨架 + `[待填]`。** |
| **测试数字必须与台账一致** | 文档 3 写「单元测试 29 个」，T1 台账也得是 29。对不上就是自曝其短。 |
| **CI/CD 文档引用真实文件，不要重贴** | `.yml` 直接引用仓库路径 + 关键片段，别把整份文件贴进 PDF（既占页又拉重复率）。 |
| **AI 报告的素材现成** | `AI留痕/` 里已有巡检记录、T? 卡、D2 卡的完整提示词与人工修改点——**这是最容易写满 4~6 页的一份**。 |
| **PDF 导出** | 答辩机不一定装了你用的软件。导出 PDF 并**嵌入字体**（中文别丢字）。 |

## 7. 留痕要求

在 `docs/大作业/AI留痕/` 下按 `AI留痕/README.md` 模板写 `D1-YYYY-MM-DD.md`，**必须包含**：

- **完整提示词**：角色创建提示词 + 每份文档的成文提示词（AI 报告要求 ≥3 处，这里天然满足）
- **素材来源表**：每份文档的每节分别取自哪个文件的哪一节
- **生成结果**：页数、章节结构、迭代轮次
- **人工修改点（≥2 处）**：AI 初稿与提示词同源 → 人工改写以免查重；AI 容易把表格原文搬进正文 → 人工重写表述
- **效率对比**：手工写 5 份 PDF 的预估耗时 vs 实际耗时

**抄送**：文档 2（架构）的类图/分层图给「PPT和设计」重绘进 PPT 第 3 页；
文档 3 的测试金字塔给 PPT 第 7 页；文档 4 的流水线图给第 8 页。
