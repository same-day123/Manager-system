## 1. 目标

补 **7 个集成测试**，真实打通 `Service → Mapper → 数据库`，并把「一次写操作跨 3 张表」的**事务一致性**验证掉——这是单元测试用 Mock 永远验证不了的部分，也是任务书点名要的「数据库事务」。

## 2. 技术方案（**已定，不要另起炉灶**）

### 2.1 为什么不用整包 `@SpringBootTest`

若依的 `RuoYiApplication` 启动时会连带拉起 **Quartz（JDBC JobStore 要连库建表）**、**Druid 数据源**、**SysConfig/SysDict 启动加载**、**Redis**。在测试环境里这些全部需要真实中间件，跑一次要几十秒还动不动失败。

所以走**最小测试上下文**：只装配「DataSource + MyBatis + laboratory 包的 Service/Mapper」，其余一律不加载。

### 2.2 四个新文件

**① `RuoYi-Vue-fast/src/test/java/com/ruoyi/project/laboratory/support/LabIntegrationTestApplication.java`**

```java
@SpringBootConfiguration
@EnableAutoConfiguration(exclude = {
        RedisAutoConfiguration.class,
        RedisRepositoriesAutoConfiguration.class,
        SecurityAutoConfiguration.class
})
@ComponentScan(basePackages = "com.ruoyi.project.laboratory")
@MapperScan("com.ruoyi.project.laboratory.mapper")
public class LabIntegrationTestApplication
{
}
```

> 排除 `SecurityAutoConfiguration` 不是因为它会报错，而是它会塞进一套默认 HTTP Basic 过滤器链，对纯 Service 层测试毫无意义还多一层干扰。`SecurityContextHolder` 属于 spring-security-core，**排除自动配置后依然可用**（T1 的 `LabTestSupport` 继续复用）。

**② `RuoYi-Vue-fast/src/test/resources/application-integration.yml`**

```yaml
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:labtest;MODE=MySQL;DATABASE_TO_LOWER=TRUE;DB_CLOSE_DELAY=-1
    username: sa
    password:
  sql:
    init:
      mode: always
      schema-locations: classpath:sql/lab-schema-h2.sql
mybatis:
  typeAliasesPackage: com.ruoyi.project.laboratory.domain
  mapperLocations: classpath*:mybatis/laboratory/*Mapper.xml
logging:
  level:
    com.ruoyi.project.laboratory: debug
```

**③ `RuoYi-Vue-fast/src/test/resources/sql/lab-schema-h2.sql`**

从 T0 产出的 `laboratory_schema.sql` 转换，五张表都要。转换规则：

| MySQL 写法 | H2 写法 |
| --- | --- |
| `bigint(20)` | `bigint` |
| `char(1)` / `varchar(n)` / `decimal(12,2)` / `date` / `datetime` | 原样保留 |
| `comment 'xxx'`（列注释） | **删掉**（H2 不支持内联 comment） |
| `) engine=innodb default charset=utf8mb4 comment='xx表'` | `)` |
| `key idx_xxx (...)`, `primary key (...)` | 保留（`key` 在 MySQL 模式可用） |
| `create table if not exists` | 保留 |

**④ `pom.xml` 加 H2 依赖——版本必须锁死**

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <version>1.4.199</version>
    <scope>test</scope>
</dependency>
```

> **必须写死 `1.4.199`。** 本机 `.m2` 仓库里只有这一个版本；Spring Boot 2.5.15 的依赖管理会指向 `1.4.200`，而项目一律用离线构建（`-o`），不锁版本就会因为拉不到 jar 直接构建失败。

## 4. 边界（**不要做**）

- **不要**让整个 `RuoYiApplication` 参与测试上下文。这是本卡最容易走偏的地方。
- **不要**给集成测试类加 `@Transactional`（理由见 2.3）。
- **不要**引入 Testcontainers、Docker、嵌入式 Redis。本机 `.m2` 里没有 Testcontainers，离线构建会失败。
- **不要**改任何 `src/main` 下的生产代码。**如果 H2 兼容性卡住了，改的是测试侧（schema / 配置），不是生产 SQL。**
- **不要**为了通过 H2 而把生产 mapper XML 里的 `sysdate()` 换成别的函数——那会改动线上行为。

## 6. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **`@EnableAutoConfiguration` 会顺手拉起一堆东西** | 除了显式排除的三个，DataSource/MyBatis 是我们要的，其余能跑起来就说明没问题。**如果启动时报某个 bean 找不到，第一反应是"多了哪个自动配置"，而不是"补一个依赖"。** |
| **`@SpringBootConfiguration` 放在测试包里是合法的** | 它只是给 `@SpringBootTest(classes=...)` 提供一个配置入口，不会影响 main 的运行。生产打包时 `src/test` 不参与，零风险。 |
| **H2 版本绝对不能省** | Spring Boot 2.5.15 的依赖管理把 h2 指到 `1.4.200`，本机 `.m2` 只有 `1.4.199`。不写 `<version>` 就会因为离线拉不到而构建失败，而且报错信息是「Could not resolve dependencies」，很容易误判成网络问题。 |
| **`KEY` 在 H2 里的可用性** | H2 的 MySQL 兼容模式支持 `key name (col)`，但如果你用的是其他 `MODE`，会直接语法错误。URL 里的 `MODE=MySQL` 不能少。 |
| **`DATABASE_TO_LOWER=TRUE` 别漏** | 少了它，H2 会把表名/列名转成大写，而 mapper XML 里写的是小写 `lab_asset`，结果就是 `Table LAB_ASSET not found`。这个参数是必须的。 |
| **`DB_CLOSE_DELAY=-1` 别漏** | 少了它，第一个连接关闭后内存库就被销毁，后面的测试会报表不存在——而且报错时机飘忽，很难查。 |
| **`@Transactional` 是个陷阱** | 加在测试类上会让所有写操作在测试结束后回滚，表面上看测试全绿，实际上你**从没验证过真实提交**。本卡明确禁止。 |
| **MyBatis Mapper 是 JDK 动态代理，`@SpyBean` 未必生效** | IT-08 的难点就在这。别硬磕，如实记录结论即可。 |
| **`typeAliasesPackage` 只指 laboratory 包** | mapper XML 的 `resultMap type="LabRepair"` 靠这个解析别名。指窄一点没关系，指错就会报 `TypeException: Could not resolve type alias`。 |
| **本机环境** | mvn 启动脚本坏了 → 用 `.workbuddy/tools/mvnx.ps1`。Git Bash 的 PATH 多次损坏（`ls`/`dirname` 找不到），跑不通就换 PowerShell，output 落了盘再读。 |
