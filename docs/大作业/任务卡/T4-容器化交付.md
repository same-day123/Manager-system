## 1. 目标

任务书把 Dockerfile 列为**可选加分项**，但它的性价比很高：**一个 `docker compose up` 就把「开发/类生产/生产三环境配置差异」这张表落地了**，比空口描述有说服力得多。同时它能顺手补掉两个真实缺口：

1. 仓库目前**无法从零跑起来**（T0 补了建表脚本，但还缺"一键起全套环境"的能力）
2. 类生产环境与生产环境的差异，可以用 `docker-compose.yml` 与 `docker-compose.prod.yml` 的 override 形式具象化

## 2. 交付内容（验收标准）

### 2.1 后端 `RuoYi-Vue-fast/Dockerfile`（多阶段）

- [ ] 构建阶段用 Maven 官方镜像，运行阶段用 JRE 8 精简镜像
- [ ] 运行阶段**以非 root 用户**运行
- [ ] 显式设定时区为 `Asia/Shanghai`
- [ ] `ENTRYPOINT` 允许通过环境变量注入配置（**不要**把密码写进镜像）
- [ ] 暴露 8080，并带 `HEALTHCHECK`

```dockerfile
# ---------- 构建阶段 ----------
FROM maven:3.9-eclipse-temurin-8 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn -B -q dependency:go-offline
COPY src ./src
RUN mvn -B -q clean package -DskipTests

# ---------- 运行阶段 ----------
FROM eclipse-temurin:8-jre-jammy
ENV TZ=Asia/Shanghai
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone \
 && useradd -m -u 1000 ruoyi
WORKDIR /app
COPY --from=builder /build/target/ruoyi.jar app.jar
RUN mkdir -p /home/ruoyi/uploadPath && chown -R ruoyi:ruoyi /app /home/ruoyi
USER ruoyi
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=5s --start-period=60s --retries=3 \
  CMD bash -c 'cat < /dev/null > /dev/tcp/127.0.0.1/8080' || exit 1
ENTRYPOINT ["java","-jar","/app/app.jar"]
```

> `maven:3.9-eclipse-temurin-8` 若在 Docker Hub 上不存在，退到 `maven:3.9-eclipse-temurin-17`。项目 `pom.xml` 的 `java.version=1.8`，两者编译产物一致，运行时一律是 JRE 8。

### 2.2 前端 `RuoYi-Vue3/Dockerfile`（多阶段）+ `nginx.conf`

- [ ] 构建阶段 Node 22，装依赖 → `vite build`
- [ ] 运行阶段 nginx:alpine，拷贝 `dist/`
- [ ] `nginx.conf` 把 `/prod-api/` 反代到后端并**剥离前缀**，同时转发真实 IP

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;        # SPA history 路由必需
    }

    location /prod-api/ {
        proxy_pass http://lab-backend:8080/;      # 末尾的 / 会剥掉 /prod-api 前缀
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1k;
}
```

> **`proxy_pass` 末尾那个 `/` 不能漏**：前端 `.env.production` 里 `VITE_APP_BASE_API = '/prod-api'`，请求路径是 `/prod-api/login`。带末尾 `/` 才会转发成 `http://lab-backend:8080/login`；不带就会变成 `/prod-api/login`，后端直接 404——而且前端只会提示"系统接口 404"，很难查。

### 2.3 根 `docker-compose.yml`

- [ ] 四个服务：`mysql` / `redis` / `lab-backend` / `lab-frontend`
- [ ] MySQL 容器启动时**自动按正确顺序**导入 7 个 SQL 脚本
- [ ] `lab-backend` 依赖 mysql 与 redis 都**健康**后再启动（`depends_on: condition: service_healthy`）
- [ ] 上传目录用命名卷持久化
- [ ] 数据库表结构初始化后，容器内导入演示数据，能直接登录

```yaml
services:
  mysql:
    image: mysql:8.0
    container_name: lab-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD:-123456}
      MYSQL_DATABASE: education_system
      TZ: Asia/Shanghai
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci
    volumes:
      - mysql-data:/var/lib/mysql
      - ./RuoYi-Vue-fast/sql:/sql:ro
      - ./deploy/mysql-init.sh:/docker-entrypoint-initdb.d/00-init.sh:ro
    healthcheck:
      test: ["CMD-SHELL", "mysqladmin ping -h 127.0.0.1 -uroot -p$$MYSQL_ROOT_PASSWORD --silent"]
      interval: 10s
      timeout: 5s
      retries: 10
      start_period: 30s
    ports:
      - "3306:3306"

  redis:
    image: redis:7-alpine
    container_name: lab-redis
    command: redis-server --requirepass ${REDIS_PASSWORD:-123456}
    healthcheck:
      test: ["CMD-SHELL", "redis-cli -a $$REDIS_PASSWORD ping | grep PONG"]
      interval: 10s
      timeout: 5s
      retries: 10
    ports:
      - "6379:6379"

  lab-backend:
    build: ./RuoYi-Vue-fast
    image: lab-asset-backend:local
    container_name: lab-backend
    depends_on:
      mysql:   { condition: service_healthy }
      redis:   { condition: service_healthy }
    environment:
      TZ: Asia/Shanghai
      RUOYI_DB_URL: jdbc:mysql://mysql:3306/education_system?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
      RUOYI_DB_USERNAME: root
      RUOYI_DB_PASSWORD: ${MYSQL_ROOT_PASSWORD:-123456}
      RUOYI_REDIS_PASSWORD: ${REDIS_PASSWORD:-123456}
      RUOYI_TOKEN_SECRET: ${TOKEN_SECRET:-change-me-in-production}
      RUOYI_PROFILE: /home/ruoyi/uploadPath
    volumes:
      - upload-data:/home/ruoyi/uploadPath
    ports:
      - "8080:8080"
    restart: unless-stopped

  lab-frontend:
    build: ./RuoYi-Vue3
    image: lab-asset-frontend:local
    container_name: lab-frontend
    depends_on:
      - lab-backend
    ports:
      - "80:80"
    restart: unless-stopped

volumes:
  mysql-data:
  upload-data:
```

> **`RUOYI_PROFILE` 为什么能生效**：`application.yml` 里 `ruoyi.profile` 写死成了 `D:/ruoyi/uploadPath`（Windows 路径，容器里根本不存在）。Spring Boot 的 relaxed binding 会把环境变量 `RUOYI_PROFILE` 映射到配置项 `ruoyi.profile`，**不需要改配置文件**。这是本项目在容器化时唯一必须覆盖的非数据库配置。

### 2.4 `deploy/mysql-init.sh`（**顺序问题的解法，别漏**）

MySQL 官方镜像会按**文件名字母序**执行 `/docker-entrypoint-initdb.d` 下的脚本。把 7 个 SQL 直接挂进去会得到这个顺序：

```
laboratory_demo_seed  → laboratory_menu_role  → laboratory_permission_fix
→ laboratory_schema   → laboratory_upgrade    → laboratory_user_seed  → ry_20260417
```

**完全反了**——`ry_20260417.sql` 最后才跑，前面的必然全部报表不存在。

所以用一个显式排序的脚本，**不要**把 `.sql` 直接挂进 initdb 目录：

```sh
#!/bin/sh
set -e
SQL_DIR=/sql
DB="${MYSQL_DATABASE:-education_system}"

for f in \
  laboratory_schema \
  ry_20260417 \
  laboratory_menu_role \
  laboratory_demo_seed \
  laboratory_user_seed \
  laboratory_upgrade \
  laboratory_permission_fix
do
  echo "==> importing $f.sql"
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 "$DB" < "$SQL_DIR/$f.sql"
done

echo "==> database initialized"
```

- [ ] 脚本必须有执行权限，或依赖 MySQL 镜像用 `sh` 执行（官方镜像对 `.sh` 会 `source`，不需要 `+x`）
- [ ] 顺序与 T0 定下的 7 步一致
- [ ] 可选：再追加 `laboratory_cleanup.sql` 做界面精简

## 3. 边界（**不要做**）

- **不要**往任何 Dockerfile 或 compose 文件里写真实密码。一律用 `${VAR:-default}` 形式并配 `.env`（`.env` 要加进 `.gitignore`）。
- **不要**为了容器化去改 `application.yml` / `application-druid.yml`。所有环境差异走环境变量——这也是「三环境规划」那张表的技术依据。
- **不要**在容器里用 root 跑后端进程。
- **不要**把 MySQL 的 3306 / Redis 的 6379 暴露到生产环境。示例 compose 里暴露是为了本地调试，生产 override 文件里要删掉。
- **不要**改 T0 产出的 `laboratory_schema.sql` 的文件名。`deploy/mysql-init.sh` 依赖它。

## 5. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **MySQL initdb 按字母序执行** | 本卡最核心的坑，见 2.4。**症状**：容器起来了但一登录就报 `Table 'education_system.sys_user' doesn't exist`，或者 MySQL 日志里一堆 "table doesn't exist"。 |
| **`RUOYI_PROFILE` 不做覆盖会怎样** | Windows 路径 `D:/ruoyi/uploadPath` 在 Linux 容器里会被当成相对/异常路径。上传资产图片、报修图片时会失败。不覆盖的话这个 bug 只有走到文件上传才暴露，很隐蔽。 |
| **`proxy_pass` 末尾斜杠** | 见 2.2 的说明。**症状**：前端所有接口 404，浏览器 Network 面板看到请求 `/prod-api/login` 返回 404。 |
| **没有 actuator** | 项目 pom 没有 `spring-boot-starter-actuator`（加它需要联网拉 jar，离线环境有风险）。所以两处健康检查都用替代方案：容器内用 bash `/dev/tcp` 探测端口，流水线冒烟用 `/captchaImage` 接口。 |
| **`/captchaImage` 依赖 Redis** | 它是若依的匿名接口，但会读写 Redis 存验证码。所以它能同时验证「后端活着」和「Redis 通着」——但也意味着 Redis 挂了它就 500。如果 CI 里没起 Redis，冒烟阶段必须允许 SKIPPED。 |
| **`mysql:8.0` 不要写成 `mysql:latest`** | `latest` 现在指向 8.4/9.x，移除了 `--default-authentication-plugin`，且默认认证插件变化会影响旧驱动。**锁定 8.0**。 |
| **`depends_on` 不等于"等它健康"** | 只写 `depends_on: [mysql]` 只保证启动顺序，不保证 MySQL 已经能接受连接。必须用长格式 `condition: service_healthy`，否则后端启动时会因连不上库直接退出。 |
| **JDBC URL 里的 `&` 在 YAML 里** | YAML 中 `&` 是锚点符号，但只在**行首或值起始**位置才特殊。写在字符串中间一般没事，**但如果报 YAML 解析错误，给整个值加引号**即可。 |
| **`.env` 要进 `.gitignore`** | compose 用的 `MYSQL_ROOT_PASSWORD` 等从 `.env` 读，这个文件不能提交。提一个 `.env.example` 作为模板。 |
| **本机环境** | 如果 Docker 没装或没启动，如实记录"跳过"，不要伪造 `docker compose ps` 的输出。答辩被问到"你这容器在哪跑的"时如实回答即可。 |

## 6. 验收方式

```bash
# 1. 构建（首次会拉镜像，慢，建议后台跑）
docker compose build

# 2. 起服务
docker compose up -d

# 3. 四个服务状态（期望 mysql/redis 为 healthy，backend/frontend 为 running）
docker compose ps

# 4. 数据库初始化是否成功（期望 5 张 lab 表 + 演示数据）
docker compose exec mysql mysql -uroot -p123456 education_system \
  -e "show tables like 'lab%'; select count(*) from lab_asset;"

# 5. 后端启动日志有没有连接错误
docker compose logs lab-backend | grep -iE "error|exception|refused" | head -20

# 6. 端到端：浏览器打开 http://localhost，用 labadmin / 123456 登录
```

**通过标准**：`docker compose ps` 四个服务全部起来；`show tables like 'lab%'` 返回 5 张表；`lab_asset` 有演示数据；能成功登录并看到运维工作台。
