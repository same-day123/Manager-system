## 5. 执行指导与踩坑

| 坑 | 说明 |
| --- | --- |
| **`userId` 千万不能设成 1** | `SysUser.isAdmin()` 的实现是 `userId != null && 1L == userId`。测试里如果用 `userId=1` 构造普通用户，`LabRoleUtils` 会把他当超级管理员，权限测试会**全绿地失真**。普通用户统一用 `100L`。 |
| **`LoginUser` 有 4 参数构造** | `new LoginUser(SysUser, Set<String>)` 不设置 `userId` 字段，`SecurityUtils.getUserId()` 会返回 `null`，然后 `insertLabRepair` 里 `user.getUserId()` 拿到 null 塞进报修单——测试会以一种很难懂的方式失败。**必须用 4 参数版**。 |
| **`validateStatusChange` 是私有方法，但不该用反射测** | 它只在 `updateLabRepair` 的 `manager == true` 分支被调用。用 `loginAs("repair_engineer")` + stub `selectLabRepairByRepairId` 就能从公开入口覆盖到，比反射更贴近真实调用路径，也更扛重构。原有那两个反射测试保留即可，不必新增反射测试。 |
| **Mockito 3.9.0 没有 mockStatic** | 若非要 mock 静态方法，需要把 `pom.xml` 的 `mockito.version` 覆盖为 `5.11.0`（本机 `.m2` 已有该 jar，离线可用），但那会把 Mockito 拉到需要 JDK 11+ 的版本，风险大于收益。**用 `SecurityContextHolder`，别动 pom。** |
| **STRICT_STUBS 会报 `UnnecessaryStubbingException`** | `MockitoExtension` 默认严格模式，`when(...)` 了但没被调用的 stub 会让整个类失败。写的时候只 stub 当前用例用到的。 |
| **`importLabAsset` 的失败分支会捕获所有 `Exception`** | 它内部是 `try { ... } catch (Exception e) { failureNum++ }`，所以要让某条数据失败，只需让 `insertLabAsset` 里的某个校验抛异常（比如 `labRoomService.selectLabRoomByRoomId` 对该条返回 null）。注意 `insertLabAsset` 是同类内部调用，**不会被 Mockito 拦截**，别指望 `verify` 它。要验证"成功插入 2 次"，应该 `verify(labAssetMapper, times(2)).insertLabAsset(any())`。 |
| **`LabAssetServiceImpl` 里注入了 `ILabRoomService` 而非直接用 mapper** | 因为 `@InjectMocks` 需要为 `ILabRoomService` 和 `LabRoomMapper` 各准备一个 `@Mock`，两个都注上了才不会 NPE。 |
| **本机环境** | mvn 启动脚本坏了 → 用 `.workbuddy/tools/mvnx.ps1` 或 `.workbuddy/tools/mvnx.sh`。Git Bash 的 PATH 曾多次损坏（`ls`/`dirname` 找不到），跑不通就换 PowerShell；PowerShell 的 stdout 有时不返回，需要 `Out-File -Encoding utf8` 落盘再读。 |
