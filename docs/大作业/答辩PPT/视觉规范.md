# 答辩 PPT 视觉规范（1 页纸）

> 交付物：D2 卡第 2.2 节要求「随 PPT 一起交」的 1 页纸。
> **一句话结论：本套答辩材料的视觉系统不是自创的，而是从系统界面代码里抄出来的。**
> 依据文件（唯一权威来源，逐项可查）：
> ① `RuoYi-Vue3/src/assets/styles/laboratory.scss` —— 业务页色板变量
> ② `RuoYi-Vue3/src/views/index.vue` —— 首页 `.lab-dashboard` 与 ECharts 色板
>
> **为什么这么做**：答辩陈述里要讲"首页与业务页是同一套设计语言"。如果 PPT 自己另起一套配色，
> 现场把 PPT 和系统界面并排一放就自相矛盾——**这份规范的每一行都是那句陈述的证据。**

| 语义浅底（图标/标签底） | `#eff6ff`｜`#fffbeb`｜`#fef2f2`｜`#f0fdf4` | `index.vue:331–334` `.metric-icon.*` |

**统一圆角 `8px`**（`laboratory.scss:18` `$lab-radius`）。

### 取样规则（三条硬约束）

1. **不新增色相**。整套材料只使用上表色值。需要"更深/更浅"时，**用透明度或填充形式表达，不新调一个色**。
2. **不加投影阴影**。系统 UI 的卡片是 `1px` 描边 + 平铺白底，**没有 shadow**（只有 `.quick-card:hover` 才出现阴影）。
   PPT 若给卡片加投影，就与系统界面不是一套了。层次靠**描边 + 底色**拉开。
3. **强调色只做点缀**。`#2563eb` 在系统里只出现在小标签、图标、图表主线上，**从不做大面积填充**。PPT 同样。

## 2. 报修状态色映射（**全篇不许换色**）

| 状态码 | 状态名 | 色值 | 表现形式 | 为什么这样分 |
| :-: | --- | --- | --- | --- |
| `0` | 待审核 | 琥珀 `#f59e0b` | 描边 | 等待人工介入，尚未进入流程 |
| `1` | 待维修 | 蓝 `#2563eb` | 描边 | 已派单，动作尚未开始 |
| `2` | 维修中 | 蓝 `#2563eb` | **实心填充** | 动作正在进行，视觉上"最实" |
| `3` | 已完成 | 绿 `#15803d` | 实心 | 终态 · 正向 |
| `4` | 已拒绝 | 红 `#dc2626` | 描边 | 终态 · 负向 |

> **这版映射修正过一次（值得记一笔）**：
> 最初想给「维修中」单独一个**深蓝**，但翻遍 `laboratory.scss` 与 `index.vue` **没有比 `#2563eb` 更深的蓝**。
> 为了一个新状态去调一个色，等于违反第 1 条「不新增色相」。
> 改成「**待维修 / 维修中同色，用描边 vs 实心区分**」——既守住了色板，又让状态机在图上呈现出**递进感**，
> 比五个孤立色块更能说明"这是一条流转链"。

配套语义：**资产状态** `0 正常` = 绿、`1 停用` = 灰、`2 维修中` = 蓝（与报修单 `2` 一致，强化"资产状态由工单驱动"）。

## 3. 字号与栅格

**画布基准 16:9 = 1920 × 1080**，**内容安全边距 100px**（四周），有效内容区 `1720 × 880`。

| 层级 | 字号 | 字重 | 用途 |
| --- | :-: | :-: | --- |
| 关键数字（Hero） | 96–120 | 700 | 单页只放一个时（如第 13 页规模指标） |
| 关键数字（并列） | 56–96 | 700 | 指标卡组（对应首页 `.metric-card strong` 30px 的放大版） |
| **页标题** | **56–72** | **700** | **每页一句结论**，最多两行 |
| 章节标签（eyebrow） | 28 | 700 | 对应首页 `.eyebrow`（蓝 `#2563eb`） |
| 正文 | 28–36 | 400 | 每页正文合计 **≤120 字** |
| 注释 / 图例 / 页码 | 22–24 | 400 | **绝对下限 22px** |

> **封面是唯一例外（已按此落地）**：封面允许**放大到标题 84px / 副标题 32px / 署名 28+24px**。
> 理由：封面只有一个视觉焦点，不需要与内页抢密度；且封面上「第 6 组 · 软件工程 2023-2 · 授课教师 谭清萱」
> 这类署名信息**必须比正文更好读**（老师会在投影上核对）。**内页仍守 56–72 上限。**

### 三条不可让步的排版规则

1. **任何文字不得低于 22px**。装不下就**拆页或删内容，绝不缩字号**——教室投影的观看距离下，<22px 必糊。
2. **页标题必须写成一句结论**，不是名词短语。
   - 反例：「资产联动」「系统架构」
   - 正例：「资产状态由报修工单驱动，不允许手工改」「四层架构，自定义代码不污染脚手架」
   - 依据：首页 `h1` 本身就写的是结论句「资产状态、报修趋势与维修成本总览」（`index.vue:6`），PPT 沿用这个习惯。
3. **每页正文 ≤120 字**。3 分钟陈述 ≈ 750 字，8 页陈述页平均每页不到 100 字——**PPT 是提词板，不是讲义**。

### 统一页骨架

```
┌─ 边距 100 ──────────────────────────────────────────────┐
│ [eyebrow 28px / #2563eb]                    [页码 22px] │  ← 顶部 100~170
│ [页标题 56–72px / #172033]                              │  ← 单行结论
│                                                          │
│  … 内容区（白卡 + 1px #d9e2ef + 8px 圆角，无阴影）…      │
│                                                          │
│ ── 1px #d9e2ef 分隔线 ────────────────── [项目简称] ──  │  ← 底部 y≈980
└──────────────────────────────────────────────────────────┘
```

## 5. 字体

| 项 | 规定 | 理由 |
| --- | --- | --- |
| 中文字体 | **思源黑体 / Noto Sans SC**（唯一实际可用） | 本机**离线**，**禁止下载任何字体**；且画布工具**实测没有「微软雅黑」**（见下方修正记录） |
| 数字与英文 | **Inter** | 系统 UI 是 Inter + 系统中文的混排 |
| 字体族数量 | **≤2 族**（当前：`Noto Sans SC` + `Inter`） | 幻灯片规范要求 |
| 行高 | 像素值（正文 28 → 行高 36；标题 56 → 行高 64） | **不用 `1.2` 这类无单位倍数** |

> **修正记录（2026-09-17，实测）**：本节原写「微软雅黑（首选）」，**实测画布可用中文字族只有
> `Noto Sans SC`、`Sarasa Gothic SC`、`Source Han Sans CN`，没有 `Microsoft YaHei`**。
> 已统一改用 **`Noto Sans SC`**（即思源黑体开源版），字形与「思源黑体」一致，结论不变。
> **导出 PDF 前请在目标机器上确认字体已嵌入**，否则改用 `Sarasa Gothic SC`（等宽更抗回退）。

## 6. 与系统 UI 的同源对照（答辩可直接引用这句）

> **「答辩材料与系统界面使用同一套设计令牌：底色 `#f4f7fb`、卡片白底 + `1px #d9e2ef` 描边 + `8px` 圆角、
> 强调色 `#2563eb`，全部取自 `laboratory.scss` 与首页 `index.vue`，没有一个是新调的。」**

**同源 ≠ 照搬**。有 2 处刻意做了"幻灯片适配"（这是规范明确允许的，也是必要的）：

| 维度 | 系统 UI（屏幕 60cm 观看） | 答辩 PPT（投影 8m 观看） | 为什么改 |
| --- | --- | --- | --- |
| 正文字号 | 14–17px | **28–36px** | 系统是**操作**界面，PPT 是**远距离阅读**界面 |
| 标题字号 | h1 = 28px | 56–72px | 同上 |
| 信息密度 | 一屏可放 13 列表格 + 4 张图 | 一页一个结论，正文 ≤120 字 | 一屏可反复看，一页只讲 20~30 秒 |

**必须一致的两项**：**色彩**（第 1 节全部色值）与 **卡片质感**（描边 + 圆角 + 无阴影）。
**刻意放大的一项**：**字号与留白**。
