## 3. 行为不变性怎么证明（本次的额外投入）

「纯重构」光说不行。除了跑测试，本次做了**两层独立证据**，因为它们覆盖的东西不一样：

- **静态证明**：证明「文案是原样搬家，不是重写」；
- **动态证明**：证明「搬家后的文案在运行期真的能渲染出原样」。

### 3.1 静态：字符串字面量级比对（工具 `.workbuddy/tools/t5_literal_proof.py`）

基线取 `git show HEAD:<file>`（改造前），判据是**字符串字面量内容精确相等**。

> **为什么不看子串包含**：`"非法的报修状态流转"`（异常文案）包含子串 `状态流转`，
> 但它是另一个字面量，不是履历动作名 —— 子串判断会报**假阳性**。第一版工具就踩了这个坑，
> 报出 2 项"残留"，人工核查后确认是误报，遂把判据改成字面量级。

按三类分别校验（改前的形态不同，判据也必须不同）：

| 类别 | 覆盖 | 结论 |
| --- | --- | --- |
| A 迁移字面量 | 15 个（4 个资产动作名 + 5 条资产文案 + 5 个报修动作名 + 1 条报修文案） | 改前在 Service ✅ → 改后 Service 已清空 ✅ → 枚举里逐字节存在 ✅ |
| B 拼接 → 模板 | 7 个拼接片段 → 4 条合成模板 | 片段改前在 Service ✅、改后清空 ✅；4 条模板在枚举里 ✅ |
| C 派生动作名 | `启用` / `停用` / `维修`（改前住在 `LabStatusUtils.assetRecordType` 的 `return` 里） | 改前方法体有 ✅ → 改后方法体**字面量清单为空** ✅ → 枚举里有 ✅；`assetRecordType` 已委托枚举 ✅ |

**全角引号专项**（本卡最容易翻车的一处）：

```
模板内容  : 报修状态由“%s”变更为“%s”
UTF-8 hex : E6 8A A5 E4 BF AE E7 8A B6 E6 80 81 E7 94 B1 E2 80 9C 25 73 E2 80 9D ...
            ↑ “ = E2 80 9C（U+201C）      ” = E2 80 9D（U+201D）
枚举里存在英文直引号版本吗 : False
```

结论：**PASS**（15 个迁移字面量 + 4 条模板 + 3 个派生动作名，全部逐字节迁移，Service 无残留手写文案）。

### 3.2 动态：脱离 Spring 的探针（工具 `.workbuddy/tools/T5EventProbe.java`）

**为什么还要这一层**：单元测试用 Mockito 只断言「Mapper 被调用了」，集成测试只覆盖到 12 个事件里的 4 个
—— 剩下 8 个事件的文案在运行期**从没被真正渲染过**。探针把 12 个事件全部渲染一遍，逐个与「改造前的
拼接写法」比对。

```
=== T5 动态验证：事件枚举 + 履历工厂（无 Spring / 无数据库）===
--- 1. 资产动作名 8 项 --- [OK] ×8
--- 2. 资产文案（对比「改造前的拼接写法」）--- [OK] ×8
--- 3. 报修动作名 + 文案 --- [OK] ×10
--- 4. 全角引号 / 分号 逐字节确认 --- [OK] ×6
     全角左引号 U+201C 位置=5 / U+201D 位置=7 / 第二次 11 与 13
     全角分号 U+FF1B 位置=6 ；模板里不得出现英文直引号 = -1
--- 5. ofAssetStatus 与 assetRecordType 同源 --- [OK] ×10
--- 6. 工厂组装契约 --- [OK] ×20
     含：operatorName 无登录上下文回落 system、createBy == operatorName、
         调拨的实验室名进 from/to 列而文案不带参数
=== 结论：PASS （通过 62 项，失败 0 项）===
```

探针**不放进 `src/test`**（那是测试负责的领地），放在 `.workbuddy/tools/`，编译运行命令写在类注释里。

## 4. 人工修改点（AI 报告素材）

> 本节是《AI 辅助开发实践报告》里「质量评估 / 人工审查」章节的现成素材，全部为真实发生的事。

### ① ★ 任务卡（AI 产出物）自身的示例代码与真实代码不符 —— 我按「行为不变」红线以代码为准

卡第 2.1 节给的枚举示例是：

```java
TRANSFER("调拨", "资产所属实验室调整：%s → %s")
```

但**真实代码**里这一处的文案是纯字面量、**不带任何参数**：

```java
// 改造前 LabAssetServiceImpl:281-282
insertAssetRecord(oldAsset.getAssetId(), "调拨", oldAsset.getRoomName(),
        newRoom == null ? String.valueOf(newAsset.getRoomId()) : newRoom.getRoomName(),
        operator, "资产所属实验室调整");
```

实验室名称（原 → 新）写在 `from_value` / `to_value` **两列**里，文案本身不带参数。
若照卡的模板实现，履历内容会从 `资产所属实验室调整` 变成 `资产所属实验室调整：A301 → B204`
—— **这是对外可见的行为变更**，而卡第 2.3 节自己把「行为逐字不变」定为**验收红线**。

**处置**：以真实代码为准，模板保留为 `"资产所属实验室调整"`（0 个占位符），并在枚举的
Javadoc 里写明「名称在 from/to 两列、不要为了更好看拼进模板」，防止后人"顺手优化"改回去。

**这条为什么值钱**：卡是 AI 写的，我是 AI，**如果无脑照卡执行就会引入一个行为变更，而 49 个
测试用例一个都不会红**（没有测试断言这条文案）。是"复核现状 vs 复核卡"这个动作把它拦下来的 ——
正好对应 AI 报告里「AI 生成内容的可信边界」与「必须以真实代码为唯一事实来源」两条结论。

### ② 全角引号：卡已经预警，仍然逐字复核

卡在第 5 节预警「AI 大概率会把 `“”` 写成 `""`」。本次实现时**没有手打**这两个字符，而是先解析
原文件的 UTF-8 字节（`E2 80 9C` / `E2 80 9D`），写完新文件后再做字节级回比（见第 3.1 / 3.2 节）。
静态与动态两层都确认：枚举里**不存在**英文直引号版本。

### ③ `SCRAP` 与 `SCRAP_BATCH` 的 `actionName` 相同，**没有**合并

`SCRAP` 与 `SCRAP_BATCH` 的动作名都是 `报废`，只有文案不同（`资产删除或报废` /
`资产批量删除或报废`）。以「消除重复」为目标的 AI 很容易把两个常量合并成一个，但那会丢掉批量删除
的文案差异 —— 属于行为变更。**判断：保留两个常量**，并在枚举 Javadoc 里写明"两个常量都要保留"。

> 顺带的实现选择：没有给枚举加"按动作名反查"的 API。因为 `报废` 对应两个常量，按动作名反查是
> **有歧义的**，一旦暴露给后人使用就是埋雷。只给真正无歧义的一处（状态码 → 事件）提供了 `ofAssetStatus`。

### ④ 卡未要求、但做的一处设计决策：把 `assetRecordType` 改成委托，而不是留着重复

卡第 2.2 节给了两个选项：`assetRecordType` 若变成无人调用，"保留并注释其为字典口径参考"，
或"改为由 `LabAssetEvent` 内部复用"。

**选择第三种、更好的写法**：让判定规则的**唯一来源**活在枚举里（`LabAssetEvent.ofAssetStatus`），
`assetRecordType` 退化为 `ofAssetStatus(status).actionName()` 的一行封装。

| 方案 | 问题 |
| --- | --- |
| 原样保留（卡的第一个选项） | 变成**没人调用的死方法**；且「状态码→动作名」变成 enum 与 util **两张表**，正是本卡要消灭的病 |
| 让枚举内部复用 `assetRecordType`（卡的第二个选项） | enum 在 `constant`、该方法在 `util`，会形成 `constant → util` 与 `util → constant` 的**字符串往返 + 包级循环依赖** |
| **本次采用** | 判定规则唯一（枚举），util 只是薄封装；对外取值逐项验证不变（第 3.2 节第 5 组 10 项断言） |

**遗留的一处如实说明**：`LabRecordFactory` 需要 `LabSecurityUtils`（操作人兜底），因此
`constant → util` 这条依赖边是**卡的结构本身带来的**；再加上既有的 `util → constant`（`LabStatusUtils`
引用 `LabConstants`），包级存在相互引用。两者同属实验室模块的工具层、不涉及
Controller/Service/Mapper/DB 的分层边界，本次按卡保留在 `constant` 包。**如果要彻底消除包级循环，
正解是把工厂移到 `util` 包**（与 `LabSecurityUtils` 同包，所有依赖边都变成 `util → constant`），
但这会偏离卡的交付路径与 §6 的验收 grep 路径，故未擅动，留作后续讨论。
