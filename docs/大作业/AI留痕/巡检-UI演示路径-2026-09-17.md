## 4. 新登记 / 待确认的答辩级问题

### D-24：真实库资产状态与种子脚本不一致（看板「5 台维修中」无对应工单）

| 项 | 种子脚本 | 真实库 | 结论 |
| --- | --- | --- | --- |
| 标为「维修中」的资产 | 2 台（`LAB-DEMO-2026-009`、`LAB-DEMO-2026-024`） | **5 台**（额外多出 2007 / 2030 / 2032） | 不一致 |
| 孤儿资产 | — | `LAB-CHEM-2026-001`（id 2007）在**任何 SQL 脚本里都查不到** | 来源不明 |
| 对应工单 | 种子里的 2 台也无工单（故意演示状态） | 多出的 3 台同样无工单 | 看板会出现「5 台维修中 / 0 条待处理工单」 |

**答辩风险**：首页开场就会显示 **「维修中资产 5」** 与 **「待审核报修 0」** 并置（见 T6-01 截图）。
老师会立刻问「5 台在修，为什么没有待处理工单？谁在修？」 → **当前数据无法自圆其说**。

**根因**：`laboratory_demo_seed.sql` 用 `where not exists(...)` 插入资产 → **只插不更新**。
真实库保留的是旧版本种子/手工操作的状态值，T0 收敛后的脚本不会覆盖它们。
多出的 3 台维修中资产，其 `lab_asset_record` 显示是 **2026-07-03 17:01 由 admin 直接做「资产状态变更」**（资料修改/维修记录），而非通过报修流程。

**修复建议（二选一）**：
1. **重跑种子前清空业务表**（或删后重新执行 `[N/7]`），让真实库与脚本一致；
2. **写一条幂等 UPDATE 脚本**把多出的 3 台改回 `status='0'`（`LAB-DEMO-2026-023/025`、`LAB-CHEM-2026-001`）。

### D-25：看板「近七日报修趋势 / 近七日维修费用」两张图为空

**证据**：T6-01 首页运维看板截图里，这两张图是平直的 0 线，右上角分别显示 **「0 单」「¥0.00」**。

**根因**：`LabDashboardMapper` 用 `date_sub()` 过滤「最近 7 天」。
当前日期 2026-09-17，而所有演示工单日期都在 2026-07-02/03（种子脚本里写死）→ 全部被时间窗口过滤掉。

**影响**：这是答辩开场画面，两张空图会被直接看到，影响演示观感。

**修复建议**：
1. 后端把趋势 SQL 改为「全部时间」或「按创建月份」聚合（推荐，避免每次演示都要调数据）；
2. 或把种子数据里的 `create_time` 改成相对当前时间的前 7 天内（代码负责 / T0 卡）。

> **PPT 使用建议**：在 D-21 修好、但 D-25 未修之前，PPT 第 9 页若用 T6-01 截图，
> 建议只裁剪左上 4 个指标卡 + 右上故障等级分布 + 左下实验室次数；**避开左下「近七日报修趋势」和右下「近七日维修费用」**两个空图区域。
