### 13.2 用的是哪条路（**零依赖，复用本项目既有的 CDP 手法**）

本机**没有 pandoc、没有 LaTeX、没有 wkhtmltopdf**，离线也装不上。选的路子是：

```
Markdown  ──(自写极简 GFM 渲染器)──▶  打印用 HTML  ──(Chrome 无头 + CDP Page.printToPDF)──▶  PDF
```

**为什么可行**：本机有 Chrome 152，且 Node 22 自带 `WebSocket` 与 `fetch`，可以直接对话 DevTools Protocol ——
这与 T6 卡里做界面截图用的是同一套手法（`cdp_shot.mjs`），**不需要引入任何依赖**。

| 脚本 | 职责 |
| --- | --- |
| `md2pdf.mjs` | GFM 子集渲染（标题／表格含对齐／代码块／引用／列表／行内 code／粗斜体／图片）；图片内联为 data URI；封面与正文分节；A4 打印 CSS；启动一次无头 Chrome 批量渲染 |
| `pdfinfo.mjs` | **不装依赖**，直接读 PDF 字节：页数（`/Type /Page`，排除 `/Pages`）、嵌入字体程序数（`FontFile2`）、`ToUnicode` 数（文字可复制的判据） |
| `build.mjs` | 遍历 `docs/大作业/文档/*.md`，批量渲染 → 核验 → 对照页数区间给 `PASS / FAIL`，整批报告落 `.workbuddy/logs/md2pdf-build.txt` |
| `build.ps1` | 纯 ASCII 包装器（调 build.mjs），**绕开 PowerShell 5.1 按 GBK 解码 `.ps1` 中文的坑** |
| `pagemap.mjs` | 量「每章落在第几页」，用于定位**是哪一段把页数撑超了**（本轮为压页数而临时加的工具，见 13.4） |

### 13.4 人工修改点（**本轮返工 4 次，全部真实发生**）

#### 修改点 1 —— 02 首次导出 **19 页**，超区间上限 15 页

- **现象**：架构文档第一版 PDF 19 页。
- **处理**：① 收紧打印 CSS（字号 10pt／行高 1.5／表格 8.4pt＋内边距 2.5-5px／边距 0.65in）；
  ② 把 7.2 节 5 张表从**单列**压成两列「字段 | 类型/约束」；③ 用 mermaid/ASCII 图处**改用手绘 SVG 真图**（同时满足「ER 图」硬指标）→ **19 → 15 → 13 页**。
- **副作用（已注意）**：同一次收紧让 01 从 10 页降到 **8 页**，贴住 8-12 的下限。**两条边界都要盯，不能只盯上限。**

#### 修改点 2 —— 05 三次压页数才进区间（8 → 7 → 7 → **6**）

- **现象**：05 初稿导出 **8 页**（区间 4–6）。
- **第一次处理**：凭感觉删了两轮，仍是 7 页 —— **盲删无效**。
- **第二次处理（关键）**：写 `pagemap.mjs` 量出真实分布，发现**正文总高 5872px ÷ 990px/页 = 5.93 页**，
  但实际排出 **7 页**。原因是打印 CSS 对表格加了 `page-break-inside: avoid`，
  **一张表放不进当页剩余空间就整张跳到下一页**，留白被浪费（本文表格密集，浪费累计约 1 页）。
- **第三次处理**：按 pagemap 的分布**定点**减内容（压缩提示词块空行、合并 3.1 与 3.2 的重复说明、把 1.3 的 3 行表改散文）
  → 正文 5648px，落 **6 页 PASS**。
- **教训**：**页数超限不要靠删手感，要靠量**。`scrollHeight ÷ 内容区高度` 与真实页数可能差 1 页（分页留白），
  所以判据要留安全余量，而不是卡在 `ceil()` 上。

#### 修改点 3 —— 单份渲染时 Chrome 偶发启动失败，会拖垮整批

- **现象**：批量构建中 02 那一次 Chrome 40s 未就绪 → 该份没出 PDF，但**后续逻辑继续跑**，报告看不出是哪份失败。
- **处理**：改为**整批只起一次浏览器**（`renderOne()` 循环复用同一 session），并给 `launchChrome` 加 **4 次重试**（换端口 + 换临时目录）。

#### 修改点 4 —— 两处「假故障」：进程 120s 不退出 与 PowerShell 吞掉 stdout

| # | 现象 | 真因 | 处理 |
| :-: | --- | --- | --- |
| a | 每次构建都像是「超时被杀」（被工具判为失败） | CDP 的 `setTimeout` 超时定时器**从不 `clearTimeout`**，事件循环被吊住 → 进程 120s 不退出 | 收到响应即 `clearTimeout(timer)` + `timer.unref?.()`；退出时用 `taskkill /T /F` 收拾 Chrome 进程树 |
| b | 脚本明明有报错，`Start-Process -RedirectStandardOutput/-Error` 却**两个文件都是空** | 本机 PowerShell 5.1 控制台按 GBK 解码 + 管道吞输出；**stdout 一律不可见** | 让脚本**自己把报告写进 UTF-8 文件**（`build.mjs` 与 `pagemap.mjs` 都改成 `say()` 双写），从文件读结果 |

> **b 这条踩了一轮才定位**：期间误以为脚本"没跑"，实际是**它的 stderr 我看不见**。
> 最后靠 `& node --check` + 把运行输出用 `[System.IO.File]::WriteAllText(..., UTF8)` 兜住才拿到 `ReferenceError: ROOT is not defined`。
> 已并入项目记忆：**本机排查脚本问题，第一件事是让脚本自己写日志文件，不要指望控制台。**
