| 部署视图（可选） | 三环境部署方式 | 依赖 T3 / T4 | ☐ |

**SOLID 素材（现成可用，不用改代码）**：

| 原则 | 应用位置 | 说明 |
| --- | --- | --- |
| **SRP 单一职责** | `LabRepairServiceImpl` | 只处理报修业务，资产状态变更委托 `ILabAssetService.updateLabAsset()`，不直接碰资产表 |
| **DIP 依赖倒置** | 所有 Controller → `ILabXxxService` → `LabXxxServiceImpl` | Controller 依赖接口不依赖实现，便于替换与 Mock 测试 |
| **OCP 开放封闭** | `LabRoleUtils` + `LabConstants` | 新增角色只改 `LabRoleUtils` 的白名单集合，所有调用方零改动 |
| **ISP 接口隔离** | 拆成 `ILabRoomService` / `ILabAssetService` / `ILabRepairService` / `ILabDashboardService` | 没有做一个 `ILabService` 胖接口；每个 Service 只暴露自己领域的方法 |

> 第 4 条 ISP 是**真实设计选择**，答辩时可以讲："我们刻意没有合并成一个实验室服务接口，因为房间管理员和维修工程师需要的操作完全不同。"

