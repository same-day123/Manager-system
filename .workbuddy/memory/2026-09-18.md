### 教训
- 推送日志里的 `RemoteException` / `CategoryInfo: NotSpecified` 是 PowerShell 把 git 的 stderr 进度输出（`Enumerating/Counting/Writing objects`）当成错误流，**只要看到 `PUSH_EXIT=0` 且最后一行是 `<old>..<new> main -> main` 就是真成功**，别被红色报错误导。
- 验证推送是否彻底同步，**别用 `origin/main..HEAD`**（用临时 token URL push 不会更新本地 `origin/main` 引用，会报 `unknown revision`）——正确做法是 `git fetch <token-url> main` 后再 `git log FETCH_HEAD..HEAD` 看是否为空。
- **⚠️ 严重教训：绝不要把明文 PAT 写进任何会被 `git add -A` 收录的文件**（本文件就是教训——把两个真实 Token 记进了记忆，触发 GitHub push protection 拦截）。Token 只允许内联在命令行 `$url` 变量里、用完即弃。写记忆/日志时一律用「（已吊销）」代指。
